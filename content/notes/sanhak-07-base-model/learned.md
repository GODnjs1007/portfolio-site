### 목표

- 목적 : 임시 라벨로 만든 연결 테스트용 모델 대신, 의사 판독 라벨이 있는 공개 데이터(PTB-XL)로 기준 모델을 학습하고 정확도와 판정 속도를 서버 관점에서 비교
    - 단계 흐름 : 6단계까지 = 서버 쪽 (전송·부하테스트) / 7단계 = 테스트 서버에 올릴 진짜 모델 만들기
- 흐름 : A 기존 AI 구조 이해 → B 학습 데이터 만들기 → C 시연·평가 데이터 분리 → E 학습·채점과 모델 비교

### A. 기존 AI 구조 이해

- 목적 : 팀에 있던 AI 코드가 어디까지 됐고 뭐가 비어 있는지 파악
- 설명 : 모델·학습·판정·워커 연결 틀은 있었지만, 의사 판독 라벨이 있는 학습 데이터를 만드는 코드가 없어서 정식 학습이 된 적이 없었음
    - 학습 : 정답이 붙은 데이터를 보여주며 모델을 만드는 것. 미리 한 번, 결과물은 파일 하나(`model.pt`)
    - 판정(추론) : 학습한 모델에 처음 보는 파형을 넣어 정상인지 물어보는 것. 실시간, 환자마다 1초에 한 번
    - R파 검출과 AI는 따로 돎 : R파는 심박수·박동 위치, CNN은 5초 파형 [3, 1250]을 통째로 보고 이상 확률을 냄

### B. 학습 데이터 만들기 (`make_ptbxl_npz.py`)

- 목적 : 공개 데이터 PTB-XL을 학습 코드가 읽는 모양으로 바꾸기
- 설명 : 12리드 중 3개만 고르고, 500Hz → 250Hz, 10초 → 5초 창 2개로 자른 뒤, 진단 코드로 정답(정상 0 / 이상 1)을 붙임
    - PTB-XL : 병원에서 누워서 잰 10초 12리드 심전도 약 2만 건. 의사 판독 라벨이 있음
    - npz : 넘파이 배열 여러 개를 파일 하나에 묶어 압축 저장하는 형식
    - 다운샘플링(decimate) : 샘플 수를 줄이는 것. 그냥 건너뛰면 높은 주파수가 낮은 주파수로 둔갑해서(에일리어싱) 필터를 먼저 걸고 줄임
    - fold 10 : PTB-XL이 같은 환자가 섞이지 않게 미리 나눠둔 10묶음 중 마지막. 시험용으로만 쓰고 학습에는 절대 안 씀
    - 환자 단위 분리 : 같은 환자 기록이 학습과 시험에 같이 들어가면 외운 걸로 점수가 부풀려짐

### C. 시연·평가 데이터 분리 (LTSTDB → INCART)

- 목적 : 부하테스트와 AI 시연에 쓸 데이터를 용도별로 나누기
- 설명 : LTSTDB는 기록마다 리드가 달라서 모델이 대부분 거부함 → 부하테스트는 LTSTDB 그대로, AI 시연·평가는 12리드인 INCART로
    - 리드 : 전극 두 개 사이의 전압 차이. 같은 심장을 다른 방향에서 본 것
    - 리드 조합 하나 = 모델 하나 : 모델은 학습한 3리드 순서로만 판정할 수 있음
    - 리샘플링(resample_poly) : 257Hz → 250Hz처럼 비율로 늘렸다 줄이며 필터를 같이 걸어 파형이 안 깨지게 바꿈

### E. 기준 CNN 학습·채점과 모델 비교 (`train.py` → `eval_ptbxl.py`)

- 목적 : GPU 장비에서 학습하고 학습에 안 쓴 시험셋으로 진짜 성적을 잰 뒤, 정확도가 오른 만큼 판정 속도를 내줘도 되는지 서버 관점에서 비교
- 설명 : 시험셋 5초 창 기준 민감도 0.929, 특이도 0.883, AUC 0.969, 창 1개 판정 CPU 0.40ms. 모델 6종 × 리드 2조합 × 시드 3번 비교에서 AUC는 0.962~0.976으로 비슷한데 CPU 판정은 0.40ms~6.55ms로 16배 차이 → 경량 CNN은 기준선, CNN+LSTM(BiLSTM)은 최종 후보
    - epoch : 학습 데이터 전체를 한 바퀴 다 본 것
    - val_loss : 학습에 안 쓴 검증 데이터에서 틀린 정도. 내려가다 다시 오르면 외우기 시작한 것(과적합)
    - 민감도 : 실제 이상 중에 이상이라고 잡은 비율 (미검출을 안 하는 능력)
    - 특이도 : 실제 정상 중에 정상이라고 맞힌 비율 (오검출을 안 하는 능력)
    - AUC : 임계값과 상관없이 정상과 이상을 얼마나 잘 가르는지. 1에 가까울수록 좋음
    - 임계값 : 이상 확률이 몇 이상이면 이상으로 판정할지 정하는 기준. 미검출이 더 위험해서 민감도 우선으로 낮게 잡음 (0.1)
    - 검증셋 vs 시험셋 : 검증셋은 임계값 고를 때 써서 점수가 후함. 시험셋은 한 번도 안 쓴 데이터라 진짜 성적
    - 시드 : 학습 시작점을 정하는 난수. 바꿔서 여러 번 돌려야 차이가 우연인지 알 수 있음
    - 채택 기준을 미리 정함 : 결과를 보고 기준을 바꾸면 원하는 결론에 끼워 맞추게 됨
    - 파라미터 : 모델이 학습으로 조정하는 숫자 개수. 많을수록 무겁고 느림
    - CNN+LSTM : 합성곱이 파형 모양(PVC)을, LSTM이 시간 순서·리듬(심방세동)을 봄
    - 데이터 증강 : 데이터를 변형해 양을 늘리는 것. 1초 겹쳐 자르기는 비슷한 창만 늘어 효과가 없었고, 진폭 조절·가우시안 노이즈 같은 다른 방법이 필요 (조교 피드백)

### 트러블 슈팅

- 학습 데이터 다운로드가 하루 넘게 걸림
    - 원인 : `physionet.org` 직접 받기가 27KB/s
    - 해결 : PhysioNet 공식 AWS 미러(`aws s3 sync --no-sign-request`)로 바꿔 2.6GB를 약 10분에
- "병목은 모델 크기"라는 가설이 틀림
    - 원인 : 데이터를 3배로 늘려도, 모델을 73배 키워도 AUC가 그대로였음
    - 해결 : 병목은 라벨(10초 라벨을 5초 창에 그대로 붙임) 쪽으로 판단. 학습보다 노이즈·외부 평가로 다음 단계를 바꿈
