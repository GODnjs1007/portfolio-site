#### A. 기능 정의

1. 주기능은 계곡에 있을 때 실시간 위험 탐지
    1. 앱은 로그인 없이 계곡 구독 , 근처 계곡 확인 후 위험하면 알림
    2. 웹은 공무원이 로그인해서 계곡 상태 확인
2. AI는 판정하지 않고 설명만
    1. AI는 왜 경보가 떴는지 쉽게 풀어줌
    2. 위험한 기준은 우리가 정해둔 규칙으로 판정
3. 작업 순서
    1. 명세서를 화면 , 서버 전에 정하고 해야지 둘이 동시에 만들 수 있음
4. 알림 3단계 (확실하게 정하지 않음)
    1. 주의 → 위험 → 재난 문자급 경고
5. 웹 기능 2개
    1. 아직 정확하게 정하지 않음. 앱이 우선순위가 더 높아서 추후 토의

- 규칙 엔진 : 정해둔 기준으로 판정하는 코드

#### B. Figma 학생 계정 및 팀 파일

- 목적 : 클로드가 피그마 화면 읽고 쓸 수 있게 학생 플랜으로 연결 및 팀원과 같이 쓸 파일 만듦
- 설명
    - 무료버전은 클로드가 읽어 코드로 바꾸는 기능 막혀있어서 학생계정으로 연동
        - 파일 개수 제한 없고 클로드랑 연결된 계정으로 파일을 내 팀에 만듦
    - 커넥터 : 클로드가 다른 서비스에 접속하게 해주는 연결
    - whoami : 지금 연결된 계정과 플랜 확인
    - 좌석 : 팀 안에서 그 사람이 쓸 수 있는 권한 등급

#### C. 깡통 화면 5장

- 목적 : 기능 정의를 눈에 보이는 화면으로 옮겨서 팀원이 다듬고 나는 API목록을 뽑아 사용하기 위함
- 설명
    - 와이어프레임 : 색, 디자인 없이 배치와 정보만 잡은 회색 화면
        - 디자인은 팀원 담당이라 어디에 정보 담을지만 표시
    - 화면 5장
        - 앱 : 홈 (구독 계곡) , 검색/구독 , 근처 계곡 (GPS) , 경보 상세
        - 웹 : 관할 계곡 상태
    - 경보 상세에 근거 보여주는 이유
        - 사전 경보만 띄우면 믿지 않기 때문에 관측소, 시각, 실측값, 기준값 같이 보여주고 AI가 풀어서 설명
    - 면책 문구 : 책임 범위를 밝히는 문장
        - 경보 판단을 돕는 정보지 공식 재난 경보가 아니기 때문에 책임범위 밝혀야 함
    - 모든 화면에 출처 넣기
        - 한강홍수통제소, 기상청 데이터는 출처 표시가 이용 조건
    - API 목록
        - 화면 마다 필요한 정보를 주는 API를 모으는 목록

#### D. 헬스체크 API와 도메인 연결

```py
@app.get("/api/health")                             # 이 주소로 GET 요청이 오면
def health():
    return {"status": "ok", "service": "yeoulmok"}  # 이 JSON을 돌려줌
```

```bash
docker run -d --name api --restart unless-stopped \   # 백그라운드로, 재부팅해도 다시 켜지게
  -p 8000:8000 \                                      # VM 8000번 = 컨테이너 8000번
  -v ~/yeoulmok:/app -w /app \                        # VM 코드 폴더를 컨테이너 안에 연결
  --env-file ~/secrets/yeoulmok.env \                 # API 키를 환경변수로 넣음
  python:3.12-slim \                                  # 파이썬만 든 가벼운 이미지
  sh -c "pip install -r requirements.txt && uvicorn app.main:app --host 0.0.0.0 --port 8000"
```

```yaml
ingress:
  - hostname: yeoulmok.ihaewon.com   # 이 주소로 들어오면
    service: http://localhost:8000   # VM 안 8000번(컨테이너)으로 보냄
  - service: http_status:404         # 나머지는 막음
```

- 목적 : 팀원의 앱이 바깥 인터넷에서 부를 수 있는 서버 주소 만들기
- 설명
    - 헬스체크 : 서버가 살아 있는지만 확인하는 가장 단순한 API
        - 진짜 기능 전에 길이 뚫렸는지 확인용도
        - 폰 → 인터넷 → Cloudflare → 집 VM → 서버
            - 이어지는지 확인했고 ok까지 확인
        - 나머지 API는 이 길 위에 얹기
    - 앱인데도 도메인이 필요한 이유
        - 앱도 인터넷으로 서버를 부르기 때문에 VM은 Tailscale 주소라 내 기기만 들어가기 때문에 공개 주소가 필요하고, 아이폰은 https만 허용해서 인증서도 필요 —> cloudflare이 해결
    - 터널을 쓰는 이유
        - 원래는 공유기 포트를 열어야 밖에서 들어오는데 그러면 집 IP가 드러나기 때문에 터널은 VM이 먼저 Cloudflare에 연결하고 요청을 받아오기 때문에 포트를 안 열어도 됨
    - venv 에서 Docker로 바꾼 이유
        - venv는 내 터미널이 서버를 붙잡고 있어서 SSH를 끄면 서버도 꺼짐
        - Docker은 docker가 대신 붙잡고 있어서 SSH를 끄거나 재부팅 해도 다시 켜짐
    - 터널을 프로젝트 별로 둠
        - 다 섞이면 하나 고장나면 다영향받음
    - 코드 바꾸면 git pull → docker restart api만 하면 됨
    - ingress : 들어온 주소별로 어디로 보낼지 정하는 규칙
    - 컨테이너 : 프로그램과 필요한 것들을 한 상자에 담아 따로 실행하는 것
    - -v : VM 폴더를 컨테이너 안 폴더에 연결

#### E. API 명세서 초안

```txt
앱:   GET /api/status?ids=1        ← 금대리 계곡 지금 상태 줘
서버: {"level": "pre_alert", "rain_1h_mm": 18.0, ...}
```

- 목적 : 앱과 서버가 같은 약속을 보고 동시에 만들기 위함
- 설명
    - API 명세서 : 앱과 서버가 어떤 주소로 뭘 보내고 뭘 받을지 정한 약속
        - 서로가 안을 몰라도 가능
    - 먼저 만드는 이유
        - 서버가 다 안 만들어져도 팀원은 응답 예시를 가짜 데이터를 넣고 화면을 먼저 만들어볼 수 있다.
    - API 목록 표

| 화면 | 이 화면에 필요한 것 | 그래서 만든 API |
| --- | --- | --- |
| 앱 홈 | 내가 구독한 계곡들 지금 상태 | `GET /api/status?ids=1,2` |
| 앱 검색 | 계곡 이름 목록 | `GET /api/valleys?q=금대` |
| 앱 근처 계곡 | 계곡 위치(위경도) | `GET /api/valleys` |
| 앱 경보 상세 | 경보 근거, AI 설명, 행동 요령 | `GET /api/valleys/{id}/alert` |
| 웹 관할 상태 | 요약 숫자 + 계곡 표 | `GET /api/admin/overview` |

- 근처 계곡 API가 없는 이유
    - 서버는 계곡 위치 목록만 주고 폰이 자기 위치랑 비교해서 거리를 계산하기 때문
    - 사용자 위치가 서버로 안 가기 때문에 위치정보 신고 대상은 아님
- 값이 없으면 0이 아니라 null
    - 0mm는 비 안 왔다는 의미고 null은 모른다는 의미다.
    - 0이라고 보내면 앱이 안전하다고 잘못 보여줄 수 있기 때문
- level은 아직 임시
- 푸시 토큰 : 서버가 특정 폰에 알림을 보낼 때 쓰는 그 폰의 주소
