#### A. 데이터 API 호출 확인

```bash
set -a; source ~/secrets/yeoulmok.env; set +a                                    # API 키를 환경변수로 불러옴
curl -s "http://api.hrfco.go.kr/$HRFCO_KEY/waterlevel/list/10M/1006664.json"     # 동부교 최신 수위 (10분 단위)
curl -s "http://api.hrfco.go.kr/$HRFCO_KEY/rainfall/list/1H/10064070/2025071900/2025071923.json"  # 서곡초교 사고일 강수 (1시간 단위)
```

```json
{ "wlobscd": "1006664", "ymdhm": "202610311200", "wl": "0.08", "fw": " " }
```

- 목적 : 코드 짜기 전 정부 API가 진짜 데이터를 주는지 확인
- 설명
    - 사용하는 API
        - 한강홍수통제소 —> 수위 (물높이) + 강수 (2개의 API)
        - 기상청 —> 관측 강수랑 강수 예보
    - 주소 읽는 법 —> 틀리면 404 에러
        - waterlevel (수위)
        - list : 값 목록
        - 10M : 10분 단위
        - 1006664 : 관측 번호
    - 날짜 자릿수가 다름 —> 틀리면 빈칸으로 나옴
        - 10분 : 12자리 (202610311200) : 분까지
        - 1시간 : 10자리 (2025071923) : 시까지
    - 값이 약간 늦게 들어옴
        - 한강홍수통제소 : 약 10분
        - 기상청 : 약 4분
        - 그래서 수집할 때 지금시간에서 10분 여유를 둬야 함
    - 빈칸이 0이 아님
        - "fw": "" 처럼 빈칸이거나 기상청 -99.9는 관측 못함의 의미
        - 0으로 처리하면 비 안 오는 거로 착각해서 위험한데도 안전하다고 판단할 수 있음 → 판정 불가로 처리
    - 관측소마다 공식 기준 수위가 존재
        - 관심 → 주의 → 경보 → 심각
    - curl : 터미널에서 주소에 접속해 응답 받아오는 명령어
    - wl / fw / rf : 수위 (m) , 유량 (m³/s , 1초에 흐르는 물의 양) , 강수량 (mm)
    - 결측 : 관측소가 그 시각 값을 못 보내 비어 있는 것

#### B. 원주 관측소 찾기

```bash
curl -s -o rf_info.json "http://api.hrfco.go.kr/$HRFCO_KEY/rainfall/info.json"  # 강수 관측소 전체 목록을 파일로 저장
grep -B2 -A4 "obsnm.*원주" rf_info.json                                          # 이름에 '원주'가 들어간 것만 앞뒤 줄과 함께 출력
```

- 목적 : 원주 안에서 우리가 쓸 강수, 수위 관측소 번호 찾기
- 설명
    - 전체 목록에서 원주만 골라내지 못 함. 중간에 짤라냄
        - 정부 서버에서 큰 목록을 끝까지 보내지 않음
    - 강수 관측소는 운 좋게 잘린 앞부분 원주 8곳 존재
        - grep으로 골라냈고 , 그 중 서곡초교랑 신촌리 유의
            - grep : 파일에서 특정 글자가 들어간 줄만 찾는 명령
                - -B2 -A4 : 앞 2줄 뒤 4줄 같이
    - 수위 관측소는 잘린 부분에 있어서 홈페이지에서 직접 찾음
        - 실시간 수문 자료 → 수위에서 원주 11곳 찾음
        - obscd = 1006664 같은 숫자로 번호를 알아냄
            - obscd : 관측소 번호
    - 번호 하나만 찍어서 부르면 잘리지 않음
        - 응답이 작아서 잘리지 않음
        - 실제 서버는 우리 관측소 몇 개만 번호로 부르니 운영에 문제 X

#### C. 대상 계곡과 사고일 데이터

| 계곡 | 상류 강수 | 하류 수위 |
| --- | --- | --- |
| 금대리 | 신촌리 (10064075) | 동부교 (1006664) |
| 서곡리 | 서곡초교 (10064070) | X |

- 목적 : 경보를 낼 계곡 정하고 각 계곡에 어느 관측소 값 쓸지 짝 지음
- 설명
    - 경보는 두 가지 데이터로 낸다.
        - 상류에 비가 많이 몰려오면 곧 물이 불어나니깐 미리 알림 (강수)
        - 하류 물이 실제로 빨리 차오르면 바로 알리기 (수위)
        - 그래서 계곡마다 위쪽 강수 관측소 + 아래쪽 수위 관측소 짝이 필요
    - 금대리는 짝이 맞지만 서곡리는 수위 짝이 없음
        - 서곡리 물 (서곡천) 은 원주 시내를 지나지 않고 서쪽 (흥업→호저)로 빠짐
            - 그래도 넣은 이유 : 실제 사고가 (2025.07.19)에 난 곳
                - 강수기록도 남아있음
            - 그래서 서곡리는 강수 경보만 하자고 제안
    - 사고일 기록 : 서곡초교 강수는 새벽 4~5시에 시간당 12,11mm (하루 약 56mm)
        - 근데 신촌리 강수량이랑 동부교 수위는 그 날 기록이 통째로 비어있음
            - 그래서 기준값은 반만 정할 수 있음
                - 강수기준 X 는 사고일 값으로 1차로 잡을 수 있다
                    - 기준값 X : 상류 1시간 강수 기준
                - 수위 기준 Y는 다른 비 온 날 기록이나 관측소 공식 기준으로 정해야
                    - 기준값 Y : 하류 30분 수위 상승폭 기준

#### D. 위치정보 법적 절차

| 기능 | 서버가 사람 위치를 받나 | 부담 |

    - 기준은 하나임
        - 이 사람이 지금 어디에 있는지

        - 서버에서 계곡 위치만 주고 폰이 자기 위치랑 비교
            - 기능은 같은데 위치가 서버로 안 가니 신고 대상이 아님
    - 웹 두 기능은 위치로 받아야 함
        - 지금 계곡에 몇 명 있나를 알리려면 사람들 위치를 모아야함
